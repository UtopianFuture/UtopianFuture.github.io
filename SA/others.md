### 稀疏模型与稠密模型

**稠密架构**

参数使用方面：稠密架构中的大部分参数在每次计算时都会被使用。也就是说，**对于输入的每一个样本，模型的所有或大部分参数都会参与到计算过程中**。
计算特点：计算密集，需要对大量的参数进行乘法和加法运算，通常会消耗较多的计算资源和内存。

虽然在计算效率上不如稀疏模型，但稠密模型凭借其全连接的特性，能够捕捉到更为丰富的特征组合，从而在复杂任务上展现出更高的精度和稳定性。

**稀疏架构**

参数使用方面：稀疏架构中**只有一小部分参数会在每次计算时被激活和使用**。模型会根据输入的具体情况，动态地选择使用哪些参数进行计算。
计算特点：计算相对稀疏，避免了不必要的计算，从而可以减少计算量和内存占用，提高计算效率。

由于减少了大量不必要的权重计算，稀疏模型在训练和推断时可以显著降低计算成本，尤其是在大规模数据集上的表现更为明显。此外，稀疏模型的存储空间需求也大大降低，有利于模型的部署和传输。

**Transformer架构**

Transformer属于稠密架构。参数使用：在Transformer中，对于每个输入序列，多头注意力机制和前馈神经网络层中的所有参数都会参与计算。例如，在多头注意力机制里，输入序列的每个位置都会与其他所有位置进行注意力计算，涉及到大量的矩阵乘法和加法运算，所有的注意力头和对应的权重矩阵都会被使用。
计算特点：Transformer的计算量随着输入序列长度的增加而显著增加，是一种计算密集型的架构。在处理长序列时，需要大量的计算资源和内存来存储中间结果。

**DeepseekV2MoE架构**

DeepseekV2MoE属于稀疏架构。DeepseekV2MoE采用了混合专家（Mixture - of - Experts, MoE）架构，其中包含**多个专家网络（experts）和一个门控网络（MoEGate）**。门控网络会根据输入数据的特征，为每个专家网络计算一个权重，然后根据这些权重动态地选择一部分专家网络来处理输入。也就是说，在每次计算时，**只有被选中的专家网络的参数会参与到计算中**，而其他专家网络的参数则不会被使用，实现了参数的稀疏使用。
计算特点：由于只有部分专家网络参与计算，避免了对所有专家网络进行不必要的计算，从而减少了计算量和内存占用。特别是在处理大规模数据时，这种稀疏计算的方式可以显著提高计算效率。例如，对于某些特定的输入，门控网络可能只选择少数几个专家网络进行处理，而其他专家网络则处于空闲状态。

### [cuda core 和 tensor core](https://www.zhihu.com/question/451127498/answer/1813864500)

cuda core是全能通吃型的浮点运算单元，tensor core专门为深度学习矩阵运算设计。**在高精度矩阵运算上 tensor cores吊打cuda cores**。

**cuda core**

一个cuda core 包含了一个整数运算单元integer arithmetic logic unit (ALU) 和一个浮点运算单元floating point unit (FPU)。然后，这个core能进行一种fused multiply-add (FMA)的操作，通俗一点就是一个加乘操作的融合。特点：在不掉精度的情况下，单指令完成乘加操作，并且这个是支持32-bit精度。 

更通俗一点，就是深度学习里面的操作变快了，你是否还记得如下的一个公式：

```
Z=W∗X+b
```

输出Z等于W乘以输入X加上bias，深度学习中，这个运算太多啦，如果是常规的运算器，会怎么处理呢？ 先把寄存器里面的数据送入乘法器，然后把结果送回寄存器，然后再把寄存器的数据送入加法器。当然实际的操作取决于硬件，至少cpu中，一般情况下要多个操作指令。

而这个**cuda core，没错，单指令完成**！

这些cuda core 在显卡里面是并行运算，就是说大家分工计算。cuda core越多，算力就越强，

于是，我们看到了接来的几代Kepler -> Maxwell -> Pascal，这些cuda core肉眼可见的增长。

虽然cuda core可以分工干活，但是对于一些场景，比如**混合精度的矩阵操作**，cuda core算得似乎不是那么高效，于是NVIDIA就开始琢磨专门针对tensor的硬件单元了：

**tensor core**

**tensor core 第一代是在volta架构上推出，**专为深度学习而设计的。也就是说他在tensor矩阵场景下算得更快。

**首先，Tensor Core的计算速度比 CUDA Core快得多。CUDA Core 每个时钟周期执行一次操作，而Tensor Core 内核每个时钟周期可以执行多个操作。**

相比于 FP32 Core 一次只能对两个数字进行计算，Tensor Core 能一次对两个 4×4 的 FP16 Tensor 进行矩阵乘计算并累加到另一个 4×4 的 Tensor 上，即 D = A * B + C，这也是其取名为 Tensor Core 的原因。

**总结**

**既然Tensor Core这么好，为什么Nv不生产一个全部是Tensor Core的深度学习专用GPU架构？**

虽然说Tensor Core是专门为加速深度学习和 AI 工作负载（例如矩阵运算）而设计，但目前深度学习也不能离开Cuda Core。

CUDA Core 针对各种并行计算任务进行了优化，更适合于通用并行计算任务。

**首先，深度学习任务其不仅仅是矩阵运算，还有很多的并行计算，这就看瓶颈在哪里了。如果瓶颈时在并行计算，那么这种类型的深度学习任务可能更适合CUDA Core。**

**其次，Tensor Core的使用是有些限制的，对于GEMM计算其效果很好，其次其输入和输出数据类型需要是半精度或单精度，矩阵的维度最好是 8 的倍数。**

当然Tensor Core也可用于通用并行计算任务，但它们可能不如 CUDA Core 高效。

通用的 GPU 中包含三种核心，分别是 CUDA Core、Tensor Core 和 RT Core，这三种核心各自具有不同的特性和功能。

- **CUDA Core**：CUDA Core 是用于通用并行计算任务的计算核心，可以执行单精度和双精度浮点运算，以及整数运算。它在处理广泛的并行计算任务方面非常高效；

- **Tensor Core**：Tensor Core 是针对深度学习和 AI 工作负载而设计的专用核心，可以实现混合精度计算并加速矩阵运算，尤其擅长处理半精度（FP16）和全精度（FP32）的矩阵乘法和累加操作。Tensor Core 在加速深度学习训练和推理中发挥着重要作用；

- **RT Core**：RT Core 是专门用于光线追踪处理的核心，能够高速进行光线和声音的渲染，对于图形渲染和光线追踪等任务具有重要意义；

### WM 在 AV 领域的应用存在的问题

**数据质量与真实性问题：模型训练的根基不稳**

- “非专家行为”数据稀缺
  现实驾驶数据多来自“专家型”的安全驾驶（如遵守交规、平稳行驶），但自动驾驶真正需要掌握的却是碰撞、急刹、违规变道等**“非专家行为”**。这类数据在现实中稀少且采集危险，导致模型对高风险场景的预测能力薄弱。
  **解决方案尝试**：如ReSim框架通过融合CARLA模拟器生成的“危险驾驶”数据，[但模拟行为与真实人类决策的差异仍存疑](https://blog.csdn.net/soaring_casia/article/details/148639201)。

- 合成数据的真实性局限
  世界模型依赖生成合成数据填补长尾场景缺口（如极端天气、动物窜出），但物理规律模拟（如轮胎摩擦系数、暴雨能见度衰减）常过于理想化。行业反馈显示：**仿真数据与实车数据的质量差距显著**，尤其在光影反射、材质纹理等细节上。

**技术瓶颈：算力、生成能力与错误累积**

- 长时生成与时空一致性的矛盾
  现有模型（如Vista、GAIA-1）普遍仅支持**短时预测（<30帧/15秒）**，分辨率也偏低（如576×1024）。若要生成分钟级高分辨率视频（如InfinityDrive的目标），需突破时空建模的算力限制。即便引入“动态信息密度调整”等技术，GPU内存消耗仍成倍增长。

- 自回归误差放大
  世界模型通过逐帧预测展开长序列（如1500帧），但初期微小误差会随迭代累积，导致后期严重偏离真实场景（如车辆位置漂移）。InfinityDrive虽设计“记忆曲线损失”抑制偏差，复杂场景中仍难根治。

- 可控性与多样性的平衡难题
  多数模型在相同初始条件下输出趋同，缺乏行为多样性（例如面对加塞车辆只会减速）。而引入随机性又可能降低动作执行精度，形成“**安全但保守**”的决策。

**可解释性与透明度缺失：黑盒决策的信任危机**

- 世界模型本质是概率驱动的生成系统，其决策逻辑（例如为何选择急转弯而非刹车）难以追溯。在L2+人机共驾场景中，**信息差可能引发驾驶员误判**：
  **案例**：蔚来系统在匝道口未充分解释“减速逻辑”，导致用户因担忧碰撞而紧急接管。
- **行业探索**：华为ADS4尝试输出“场景意图文本”（如“检测行人，减速通过”），但复杂决策的语义化仍不成熟。

**安全验证困境：仿真无法替代真实风险**

- 极端场景的覆盖不足
  尽管模型可生成“爆胎”“雪崩”等罕见事件，但此类场景的物理参数（如路面附着系数突变）缺乏实测校验，**仿真可靠性存疑**。

- 责任归属模糊
  L3级以上系统要求车企对事故负责，但世界模型的“平行宇宙”训练结果能否作为安全认证依据？**监管框架尚未同步技术发展**。

**系统整合挑战：从预测到行动的鸿沟**

- 规划与控制的割裂：世界模型擅长生成视频，但将其转化为车辆动作（如方向盘转角、油门开度）需额外模块（如ReSim的Video2Reward）。这些模块可能引入新误差，且增加延迟。
- 多传感器融合瓶颈：Dream to Drive等模型依赖抽象环境表征（如道路拓扑），而非原始摄像头数据，导致**细节感知能力受限**。

**世界模型的进化方向与行业意义**

尽管存在上述问题，世界模型仍是自动驾驶突破长尾场景的核心路径。技术迭代正从三方面推进：

- **数据融合**：混合真实日志与增强仿真（如危险场景生成）；

- **算法优化**：时空解耦训练（InfinityDrive）、可微分物理引擎（Dream to Drive）提升精度；

- **人机协同**：意图可视化（蔚来透明寻路）建立用户信任。

若算力成本下降与多模态大模型结合（如VLA），世界模型有望成为L4级自动驾驶的“核心推演引擎”，但需警惕**过度依赖仿真导致的现实泛化失灵**。车企与供应商的竞合（如特斯拉纯视觉vs.激光雷达派）将决定技术路线的收敛或分化。

### [Diffusion 扩散模型](https://zhouyifan.net/2023/07/07/20230330-diffusion-model/)

核心：通过文字生成图片。

Diffusion 模型的骨干网络通常是改进的 **UNet**，其设计解决关键挑战：

- **多尺度特征融合**： 通过编码器（下采样）捕获上下文，解码器（上采样）恢复细节，跳跃连接保留空间信息；
- **时间步嵌入**： 将时间步 t 通过正弦位置编码或 MLP 转换为向量，作为网络每一层的条件输入，告知模型当前去噪阶段；
- **注意力机制**： 在编码器/解码器中加入 **Self-Attention** 层捕捉长程依赖；对于条件生成（如文本到图像），加入 **Cross-Attention** 层融合条件信息（如 CLIP 文本嵌入）。

### MoE 专家模型

模型规模是提升模型性能的关键因素之一。混合专家模型 (MoE) 的一个显著优势是它们能够在远少于稠密模型所需的计算资源下进行有效的预训练。这意味着在相同的计算预算条件下，可以显著扩大模型或数据集的规模。特别是在预训练阶段，与稠密模型相比，混合专家模型通常能够更快地达到相同的质量水平。

在混合专家模型 (MoE) 中，将**传统 Transformer 模型中的每个前馈网络 (FFN) 层替换为 MoE 层，其中 MoE 层由两个核心部分组成: 一个门控网络和若干数量的专家**。MoE包括以下核心组件：

- 专家。在MoE架构中，专家是专门针对特定任务的子模型。专家拥有不同领域的专业知识，负责处理不同的计算任务或者特定输入子空间。形式上，每个专家网络fi（通常是一个linear-ReLU-linear网络）由参数W来参数化，接受输入x并生成输出fi(x;Wi)。

- 门控函数（也称为路由函数或路由器）：门控函数负责协调专家计算，即判定哪个输入样本应该由哪些专家处理，哪些专家将被激活并参与到当前的计算中。形式上，**门控函数G（通常由linear-ReLU-linear-softmax网络组成）**由参数O来参数化，接受输入x并产生输出。

  门控网络负责为每个输入 token 选择一个稀疏的专家组合，这些专家将参与到当前的计算中。门控函数是一个可以执行一系列非线性变换的网络，该网络对概率分布进行建模，根据概率去做出相应的选择。门控网络由学习到的参数组成，并且与网络的其余部分同时进行预训练。一个典型的门控网络就是一个带有 softmax 函数的简单网络。

- 聚合层（Combining Layer）：聚合层负责整合专家网络的输出，以形成最终的输出结果。很多资料并没有把聚合层单独罗列出来。

### 主干网络

在自动驾驶算法中，尤其是**感知模块**（负责识别和理解周围环境），经常提到的“主干网络”是指**负责从原始输入数据（主要是图像，也包括点云等）中提取多层次、鲁棒性强的特征表示的核心深度神经网络架构。**

你可以把它想象成整个感知系统的大脑皮层，负责**初步但至关重要的信息处理**：

- **核心任务：特征提取**

  - 输入：原始传感器数据（摄像头图像、激光雷达点云、雷达数据等）。

  - 输出：一系列具有**丰富语义信息**的**特征图**。这些特征图不再是原始的像素或点，而是编码了图像/点云中物体、结构、纹理等高级信息的数据表示。

  - 过程：主干网络通过一系列卷积层、池化层、非线性激活函数等操作，逐步将低级的、像素级的细节信息（如边缘、角点）抽象、组合成更高级的、更具语义意义的特征（如“车轮”、“车窗”、“人脸”、“车道线”、“建筑物轮廓”等）。

- **关键特性：**

  - **分层结构：** 主干网络通常是分层的（如卷积神经网络的多个卷积块）。浅层提取局部细节特征（边缘、纹理），深层提取全局语义特征（物体、场景）。这种多尺度特征对于自动驾驶至关重要，因为需要同时检测近处的小物体（如交通标志）和远处的大物体（如车辆）。

  - **预训练与迁移学习：** 绝大多数自动驾驶系统不会从头训练主干网络。它们通常使用在大型通用图像数据集（如ImageNet）上预训练好的模型（如ResNet, VGG, EfficientNet, MobileNet, DenseNet, Vision Transformers等）。这些预训练模型已经学会了强大的通用视觉特征提取能力。然后，在自动驾驶特定的数据集（包含各种道路场景、车辆、行人、交通标志等）上进行**微调，使主干网络更适应驾驶场景的特殊性。** 这大大提高了训练效率和最终性能。

  - **效率与精度平衡：** 主干网络的选择是算法设计的关键权衡点：
    - **精度优先：** 选择更深、更宽的网络（如ResNet-152, EfficientNet-B7），能提取更丰富的特征，但计算量大，推理速度慢。
    - **速度/效率优先：** 选择更轻量级的网络（如MobileNet系列, EfficientNet-Lite, ShuffleNet），推理速度快，适合嵌入式平台或实时要求高的场景，但特征提取能力可能稍弱。
    - 自动驾驶需要在实时性（通常要求几十毫秒内完成推理）和准确性之间找到最佳平衡点。

- **在自动驾驶感知系统中的作用：**

  - **输入：** 主干网络是感知流水线的**第一站**（或紧随数据预处理之后）。它接收原始的传感器数据。

  - **输出：** 主干网络输出的**特征图**是后续所有感知任务的**基础**。这些特征图被输入到不同的“任务头”网络中：
    - **物体检测头：** 基于特征图预测边界框和类别（车辆、行人、骑行者等）。(e.g., Faster R-CNN, YOLO, SSD 中的骨干)
    - **语义分割头：** 对特征图中的每个像素进行分类（道路、人行道、天空、车辆等）。
    - **实例分割头：** 区分同一类别的不同个体（不同的车辆、不同的行人）。
    - **车道线检测头：** 识别车道标记。
    - **深度估计头：** 估计场景中各点的距离。
    - **目标跟踪模块：** 利用特征进行目标关联。

  - **共享特征：** 主干网络提取的特征通常被**多个下游任务共享**。这意味着输入数据只需经过主干网络一次，其输出的特征就可以被多个检测头/分割头同时使用，大大提高了系统的效率。这也是像“多任务学习”架构（如特斯拉早期的**HydraNet**）的核心思想。

**总结来说，主干网络在自动驾驶感知算法中是：**

- **特征提取引擎：** 将原始传感器数据转化为高级语义特征。
- **预训练知识载体：** 利用在大规模数据集上学到的通用视觉知识。
- **计算效率与精度的关键点：** 选择合适的主干直接影响系统实时性和准确性。
- **多任务学习的基础：** 为下游的各种感知任务（检测、分割、跟踪等）提供共享的特征表示。

**常见的主干网络例子：**

- **CNN-based:** ResNet (及其变种 ResNeXt, ResNet-D), VGG, MobileNet (v1/v2/v3), EfficientNet (B0-B7, V1/V2), DenseNet, CSPNet (常用于YOLO系列), Darknet (YOLO自研骨干)。
- **Transformer-based:** Vision Transformer, Swin Transformer, PVT - 近年来在自动驾驶感知中也展现出强大潜力，尤其擅长建模长距离依赖关系。

### BEV

**BEV的核心思想是：将所有传感器信息（尤其是多摄像头图像）通过算法“投影”或“转换”到一个统一的、车辆正上方的二维俯视网格地图中**。在这个坐标系中：

- 车辆自身位于网格中心；
- X轴指向车辆前进方向；
- Y轴指向车辆左侧；
- 每个网格单元可能包含语义、高度、速度等信息。

### BEVFormer

BEVFormer是一种基于Transformer架构的鸟瞰图（Bird's-Eye View, BEV）编码器，专为自动驾驶感知任务设计。它通过融合多视角摄像头数据，生成统一的时空BEV特征表示，支持3D物体检测、地图分割等多种任务。核心设计原理如下：

- **统一BEV表示生成**
  BEVFormer将多视角摄像头图像（如车辆前、后、左、右视图）通过预定义的**网格状BEV查询**（Grid-shaped BEV Queries）投影到俯视视角的2D平面坐标系中。这种表示消除了透视畸变，提供以车辆为中心的全局环境视图。

- **时空特征融合**

  - **空间交叉注意力（Spatial Cross-Attention, SCA）**
    每个BEV查询与多视角图像中**感兴趣区域的特征**动态交互。例如，查询通过3D参考点投影到不同相机视图，聚合关键的空间信息（如障碍物位置、车道线形状）；

  - **时间自注意力（Temporal Self-Attention, TSA）**
    引入历史BEV特征（如前2秒的数据），通过循环机制融合时序信息。例如，当前查询与前一时间戳的BEV特征交互，提升运动物体速度估计和被遮挡物体的检测能力。

### BEV 空间和 2D 空间

从技术本质看，**BEV和2D图像的核心区别在于几何表达方式**。2D图像是透视投影的结果，遵循“近大远小”原则，距离相机15米的行人可能只占10像素，而5米处的车辆占100像素。这种非线性尺度变化给感知算法带来巨大挑战——同一个物体在不同距离会呈现不同尺寸，传统CNN难以泛化。

而BEV通过几何变换将三维世界投影到二维俯视平面，实现了“上帝视角”的等距表达。在BEV网格中，每个单元格代表固定物理尺寸（如0.2m×0.2m），因此10米外的行人和3米外的自行车占据的网格数量与其实际物理尺寸成正比。这种空间一致性正是规划模块需要的——规划需要知道“前方5米有2米宽的障碍物”，而非“图像第120行有50个连续白色像素”。

不过BEV的构建存在根本性挑战：从2D到BEV的转换是病态问题。单目相机无法通过单帧图像确定深度，就像人类闭一只眼难以判断远处物体的精确距离。这也是为什么LSS要预测深度分布，而BEVFormer用Transformer学习隐式几何先验。有趣的是，人类驾驶员其实也在做类似BEV的脑补——根据运动视差、物体先验尺寸等信息重建三维世界，只不过神经网络用反向传播代替了生物进化。

### 占用网络（Occupancy）

占用网络（Occupancy Network）是自动驾驶领域一种**基于三维体素（Voxel）的通用场景感知方法**，其将环境划分为密集的3D网格（如0.2m×0.2m×0.2m），逐个体素预测其状态，构建一个“高精度的3D占用地图”。它直接预测空间中每个位置的“占用状态”和语义信息，**无需预先定义物体类别或几何形状**。这种技术彻底改变了传统依赖“边界框（Bounding Box）”的感知范式，成为应对**未知障碍物、不规则物体、动态场景**的核心解决方案。

**传统方法的局限**

- **无法处理未知障碍物**
  传统检测器只能识别训练集中见过的类别（如车辆、行人），但现实中存在**掉落货物、动物、施工锥桶**等长尾物体。

- **对不规则物体建模能力差**
  边界框难以精确表示**树枝、变形车辆、异形建筑**等非刚性物体。

- **遮挡与边缘模糊问题**
  边界框在遮挡场景下易漏检（如半辆车在墙后），且框内包含大量空区域。

- **高度信息缺失**
  2D检测无法判断物体的垂直结构（如隧道高度限位、天桥通过性）。

占用网络通过**像素级空间建模**解决了这些问题。

**如何构建占用网络**

- **输入数据融合**

  - **多摄像头图像**：通过BEVFormer等生成BEV特征；

  - **激光雷达点云**：直接体素化或与图像特征融合；

  - **时序信息**：融合历史帧提升运动物体预测；

- **网络架构关键模块**

| 模块               | 功能                                                         |
| :----------------- | :----------------------------------------------------------- |
| **3D体素编码器**   | 将点云/图像特征转换为3D体素特征（常用3D稀疏卷积）            |
| **BEV-3D特征转换** | 将BEV特征提升到3D空间（如特斯拉Occupancy Network的“BEV to 3D”模块） |
| **时空融合模块**   | 聚合多帧数据预测动态物体轨迹                                 |
| **占用解码器**     | 输出每个体素的占用概率、语义类别、运动速度                   |

**输出表示**

- **占用概率**：体素是否被占据（0~1）
- **语义标签**：如“车辆”“行人”“可行驶区域”“未知障碍物”
- **流场（Flow）**：动态物体的运动向量（速度+方向）

### DSO

DSO（Direct Sparse Odometry）是一种基于**直接法**的视觉里程计（VO）算法，由德国慕尼黑工业大学Jakob Engel等人于2016年提出。它通过直接利用图像像素的亮度信息（而非特征点）估计相机运动，并**构建稀疏环境地图**，在弱纹理场景中表现出优异的鲁棒性。

### SLAM

**SLAM（Simultaneous Localization and Mapping，同步定位与建图）** 是机器人及自动驾驶领域的核心技术，旨在解决一个关键问题：

> 当设备处于未知环境中，如何实时构建环境地图并同时确定自身在地图中的位置？

**SLAM的核心任务**

- **定位（Localization）**

  - 实时计算设备自身在环境中的 **6自由度位姿**（3D位置 + 3轴朝向）。

  - 示例：自动驾驶车辆需知道自身在车道中的精确位置（厘米级精度）。

- **建图（Mapping）**
  - 根据传感器数据构建环境模型，包括：
    - **几何地图**（障碍物位置、道路结构）
    - **语义地图**（车道线、交通标志等）
    - **拓扑地图**（路径连通关系）

SLAM 鲁棒性不行，尤其是当自动驾驶场景里面都是动态物体的时候，用它来做定位太难了，简直就是灾难。所以当前大家都不用 SLAM 了，转向BEV，transformer，occupancy network 等算法。

### Lidar 与 camera 融合

现有融合策略可分为三级：**数据级、特征级和 BEV 级融合**。

- 数据级融合方法**通过相机投影矩阵将激光雷达点云投影到图像**，投影的稀疏深度图可与图像数据共同输入网络，或与图像语义特征结合以增强输入；

- 特征级融合方法**在特征空间通过 Transformer 融合不同模态**：先生成激光雷达特征图，再通过交叉注意力在激光雷达特征上查询图像特征，最后拼接用于下游任务；

- BEV 级融合方法分别提取激光雷达和图像的 BEV 特征，再通过拼接或融合模块进行融合。例如，HDMapNet使用 MLP 将相机分支的 PV 特征映射到 BEV 特征，激光雷达分支使用 PointPillars 编码 BEV 特征；近期 BEVFusion 工作在相机分支使用 LSS 进行视图变换，激光雷达分支使用 VoxelNet，最终通过 BEV 对齐模块融合。

SuperFusion 结合三种融合方式，充分利用两种传感器的互补属性。

- Depth-Aware Camera-to-BEV Transformation（数据级，利用 LiDAR 数据将 2D 图像投影到 BEV 空间）

  上图左上角所示，利用 LiDAR 的数据将 camera 投影到 BEV 空间。将 RGB 图像和由 LiDAR 点云数据投影来的稀疏深度图像作为输入，传递到 Camera Backbone。Camera Backbone 有两个分支：1）提取 2D 特征图；2）连接到一个深度预测网络，估计 RGB 图像中每个元素的深度，为了更好的估计深度，还会将稀疏深度图像生成一个密集深度图像，同样传递到深度预测网络中。最终生成 Camera BEV 特征图。

- Image-Guided LiDAR BEV Prediction（特征级）

  激光雷达分支中，使用 PointPillars 结合 dynamic voxelization 作为点云编码器，为每个点云 P 生成激光雷达 BEV 特征 B。

  该模块为编码器 - 解码器网络：编码器通过若干卷积层将原始 BEV 特征 L 压缩为瓶颈特征 B，随后应用**交叉注意力机制**动态捕捉 B 与图像特征 F 的关联。通过三个全连接层将瓶颈特征 B 转换为查询 Q，图像特征 F 转换为键 K 和值 V，注意力亲和矩阵由 Q 和 K 的内积计算，表征激光雷达 BEV 中每个体素与对应相机特征的关联，经 softmax 归一化后用于加权聚合值 V 得到聚合特征 A。随后对聚合特征 A 应用卷积层降维，与原始瓶颈特征 B 拼接，再经卷积层得到最终瓶颈特征 \(B'\)。此时 \(B'\) 包含图像特征的视觉引导，输入解码器生成补全并预测的激光雷达 BEV 特征 \(L'\)。通过此方式，在特征级融合双模态以更好预测长距离激光雷达 BEV 特征。

### 交叉注意力

**交叉注意力（Cross-Attention）** 是Transformer架构中的核心机制，用于实现**不同模态或不同空间特征之间的动态信息融合**。在自动驾驶的BEV感知（如BEVFormer）中，它通过让BEV查询（Query）主动“关注”图像特征（Key/Value），实现2D到BEV的智能映射。

**与自注意力的区别**

| **特性**     | **自注意力（Self-Attention）**    | **交叉注意力（Cross-Attention）** |
| :----------- | :-------------------------------- | :-------------------------------- |
| **输入**     | Q, K, V 来自同一特征集            | Q 来自目标模态，K/V 来自源模态    |
| **功能**     | 特征内部交互（如BEV网格间的关系） | 跨模态/跨空间特征融合（图像→BEV） |
| **典型应用** | BEVFormer的时序自注意力模块       | BEVFormer的空间交叉注意力模块     |

### NeRF

NeRF（Neural Radiance Fields，神经辐射场）是一种基于深度学习的 **3D场景隐式表示方法**，它通过神经网络将空间任意点的颜色和密度编码为连续函数，实现从2D图像到逼真3D重建的突破。在自动驾驶领域，**NeRF正成为提升环境感知与仿真能力的核心技术**。

### RLHF

**RLHF（Reinforcement Learning from Human Feedback，基于人类反馈的强化学习）** 是一种将**人类偏好**融入AI模型训练的范式，通过强化学习（RL）引导模型输出符合人类价值观的高质量结果。它是大语言模型（如ChatGPT）和自动驾驶决策系统的核心训练技术，解决了传统方法中“目标难以量化定义”的难题。

### Softmax

对每个元素取指数后除以所有元素指数的和。这个设计确保了输出值在0到1之间且总和为1。

### GEMM

```python
def gemm(A, B):
    m, k = A.shape
    k, n = B.shape
    C = zeros((m, n))
    for i in range(m):
        for j in range(n):
            for p in range(k):  # 向量内积
                C[i][j] += A[i][p] * B[p][j]
    return C
```

通用矩阵乘，A(m,k) * B(k, n) = C(m, n)，输出一个 m*n 的矩阵。

### GEMV

矩阵乘向量。

### GEMM 和 GEMV 在 LLM 中的使用

- 在训练阶段和推理阶段（处理整个输入序列时），主要使用GEMM；

- 在推理阶段（自回归生成token时），对于当前新token的计算，除了与整个序列相关的操作（如 attention score 的计算需要历史序列，但历史序列已缓存）外，对于当前token的处理，大部分操作退化为GEMV（**因为当前token的表示是向量**）。

注意：在推理中，为了效率，通常会缓存历史序列的K和V（避免重复计算），因此当计算当前token时，K和V矩阵是不断增长的（直到最大长度）。所以，在计算attention score 时，当前token的Q向量需要与所有历史token的K矩阵相乘，这是一个矩阵-向量乘法（GEMV）或一个行向量与矩阵的乘法（结果是一个行向量）。

 因此，我们可以将使用阶段归纳如下：

| 阶段                    | 训练 | 推理（初始完整序列） | 推理（自回归生成单个token） |
| ----------------------- | ---- | -------------------- | --------------------------- |
| 嵌入层                  | GEMM | GEMM                 | GEMV                        |
| 线性投影（Q/K/V）       | GEMM | GEMM                 | GEMV                        |
| attention score（QK^T） | GEMM | GEMM                 | GEMV                        |
| 注意力加权求和（AV）    | GEMM | GEMM                 | GEMV                        |
| 前馈网络 FFN            | GEMM | GEMM                 | GEMV                        |
| 输出层                  | GEMM | GEMM                 | GEMV                        |

 注意：在推理的初始步骤（处理整个上下文时），所有操作都是GEMM（因为输入是矩阵）。而在自回归生成步骤，除了注意力得分和加权求和涉及历史序列（矩阵）外，其他操作（投影、前馈、输出）都是**对当前单个token的向量进行操作，因此是GEMV**。

 另外，在多头注意力中，上述操作在多个头上并行执行，但计算类型不变（GEMM或GEMV）。

 所以，在优化大模型推理性能时，针对GEMV操作的优化（如使用专用硬件指令）非常重要，因为自回归生成的大部分时间都在执行GEMV。

### GEMV 访存

由于下面原因，**矩阵乘向量操作是明显的访存bound**，而 GEMV 是LLM推理中最主要的部分，这也就导致LLM推理是访存bound类型。

**计算公式**：y = A * x。其中 A 是 m * n 矩阵；x 是 n * 1 向量；y 是 m * 1 结果向量。

**计算过程**：对输出 y 的每个元素 y_i，需遍历矩阵 A 的每一行和向量 x 的所有元素。

**计算强度极低**

- **计算量**：每个 y_i 需要 n 次乘加运算，故**总计算量 = 2mn FLOP**

- **数据访问量**：

  - 读取矩阵 A：mn 个元素

  - 读取向量 x：n 个元素

  - 写入结果 y：m 个元素

    故**总数据量 = mn + n + m 字节**

- **计算强度**：
  Compute Intensity=FLOP/Bytes≈2mn/(mn+n+m)
  **现实场景**：m=4096, n=4096 时，强度仅 **0.5 FLOP/Byte**（因数据需多次加载）

> 💡 对比：GEMM（矩阵乘矩阵）强度可达 **50-100 FLOP/Byte**（通过分块复用数据）

**数据复用率为零**

- **向量 x 的访问模式**：
  计算每个 y_i 时，x 的每个元素 x_j 仅被使用**一次**，x 无法驻留在高速缓存（Cache）中，必须反复从内存加载。
- **矩阵 A 的访问模式**：
  按行访问（非连续），且每行数据仅用一次，无时间局部性（Temporal Locality）。

**缓存失效（Cache Thrashing）**

- **场景示例**：
  当 m 很大时（如 m=32K），y 向量占用 256 KB，而L2 Cache仅 6 MB：
  - 计算不同 y_i 时，矩阵 A 的不同行会互相覆盖Cache。
  - 向量 x 因跨行访问被反复驱逐，**Cache命中率趋近于0**。

### CUDA core

众所周知，冯诺依曼体系结构是现代计算机的基础，它包含了五个基本部件：运算器、控制器、存储器、输入设备和输出设备。其中，运算器和控制器合称为中央处理器（CPU），存储器包括内存和外存，输入设备和输出设备合称为外设。CPU 通过总线与内存和外设进行数据交换。

![img](https://picx.zhimg.com/v2-687bbfe313280044512c7bbd5782b115_1440w.jpg)

经过近几十年的高速发展，这些基本部件都变得无比复杂且强大。对于 CPU 来说，它的核心频率已达到数 GHz，核心数量也达到数十甚至上百个。而存储器则发展出了多层次的体系结构，包括一级缓存、二级缓存、三级缓存、内存、硬盘等。

但即便拥有这无与伦比速度的现代 CPU + 内存体系，人们仍然在不断尝试新的方法冲刺计算性能上限。随着摩尔定律逐渐失效，提高 CPU 频率变得越来越困难，因此提高处理器的核心数量就成了一种收效更好的方法。

通过提升处理器核心数量来提升计算性能这种思路促进了并行计算理论以及应用技术的发展，从而诞生了 GPGPU 这一概念。从体系结构上来看，GPU 技术扩展了冯诺依曼结构中的运算单元，将其从单个变成了多个。

![img](https://pic2.zhimg.com/v2-f2dbb5e0a8c9216f5350949743253ec9_1440w.jpg)

也就是说，一个控制单元对应多个运算单元，这样一来，**每条指令可以同时运行在多个运算单元上，这种模式也被称为 [SIMT](https://zhida.zhihu.com/search?content_id=235830808&content_type=Article&match_order=1&q=SIMT&zhida_source=entity)（Single Instruction Multiple Thread，单指令多线程），**SIMT 是 GPU 实现 SIMD (Single Instruction Multiple Data, 单指令多数据) 的方式。

需要注意的是，GPU 的这种创新与 CPU 的多核心不是一个层次的概念，多核 CPU 的每个物理核心仍然是单线程的（虽然CPU有超线程技术，但只是逻辑上的双核心）。另一方面，虽然 CPU 也能实现 SIMD，但 CPU 的实现方式是增加寄存器宽度，然后使用扩展指令（SSE，AVX等）执行运算，从而达到向量化计算的效果。由于寄存器数量有限，因此 CPU 核心的并行能力相对于 GPU 来说是非常有限的。

[流式多处理器](https://zhida.zhihu.com/search?content_id=235830808&content_type=Article&match_order=1&q=流式多处理器&zhida_source=entity) (Streaming Multiprocessor, SM)可以看作是 GPU 的处理核心，同 CPU 的多核设计类似，GPU 也有多个流式多处理器（通常远超 CPU 的核心数量），比如 GA100 有 128 个 SM，GV100 有 84 个 SM。深入到 SM 内部来看，它又被划分成多个处理块（Processing Block），这里所谓的**处理块**就是我们前面提到的单指令多线程单元，它的控制单元包含指令缓存（Instruction Cache）、线程束调度器（Warp Scheduler）、分配单元（Dispatch Unit）等组件，而运算单元则包含一大堆各种类型的处理核心，官方术语叫流处理器（Stream Processor, SP），这些 SP 被分为多个组，有的负责 INT 运算，有的负责 FP16 运算，以及 FP32，FP64 等等，从软件层面来看，他们又被称为 CUDA Core。

![img](https://pica.zhimg.com/v2-3078ecb5733713b59c138b3a37ba9f72_1440w.jpg)

CUDA是Computer Unified Device Architecture的缩写，是GPU并行编程处理和直接访问Nvidia GPU指令集API的总称，它适用于流行的编程语言C/C++，方便用户调用。
CUDA Core则为GPU中的处理单元，如果将GPU比作工厂，那么CUDA Core就是其中的流水线，如果想生产更多的产品，就需要使用更多的流水线。

GPGPU中有三种核心，分别是CUDA Core、Tensor Core、RT Core；如果把每种Core都比作流水线的话，那么GPGPU就存在三类流水线。

  - 最核心的是，每个线程束Warp包含16个CUDA Core，每一个CUDA Core由1个浮点数单元FPU和1个逻辑运算单元ALU组成。
  - 一个CUDA Core包含了一个整数运算单元(INT Unit)和一个浮点数运算单元(FPU)。每个Core能够进行一种原子性的fused multiphy add(FMA)操作。CUDA Core可以实现单指令完成累加乘操作。

```python
def conv2d(input, kernel):
    H, W = input.shape
    K, _ = kernel.shape
    out_h = H - K + 1
    out_w = W - K + 1
    output = zeros((out_h, out_w))
    for i in range(out_h):
        for j in range(out_w):
            window = input[i:i+K, j:j+K]  # 滑动窗口
            output[i][j] = np.sum(window * kernel)  # 逐点相乘后求和
    return output
```

### 大模型的参数

大模型的参数主要在以下四个阶段被使用，贯穿整个 Transformer 架构的计算过程：

- **嵌入层 (Embedding Layer)**

- **注意力机制 (Attention Layers)**

- **前馈网络 (Feed-Forward Network)**：FFN(x)=ReLU(x⋅W1+b1)⋅W2+b2FFN(*x*)=ReLU(*x*⋅*W*1​+*b*1​)⋅*W*2​+*b*2​；

- **归一化层 (LayerNorm)**：缩放因子 gamma 和偏移量 beta；

**参数占比**（以 GPT-3 175B 为例）：

| 组件       | 参数占比 |
| :--------- | :------- |
| 词嵌入     | 30%      |
| 注意力矩阵 | 40%      |
| 前馈网络   | 25%      |
| 归一化层   | <5%      |

**计算示例：Self-Attention 阶段参数使用**

```python
# 输入：X [n×d_model]
# 参数：W_Q, W_K, W_V [d_model×d_k]

# 1. 投影计算（使用参数）
Q = X @ W_Q  # GEMM
K = X @ W_K  
V = X @ W_V  

# 2. 注意力得分（无参数）
S = Q @ K.transpose() / sqrt(d_k)  # GEMM
A = softmax(S)  # 无参数

# 3. 加权输出（无新参数）
O = A @ V  # GEMM
```

大模型的所有能力本质上来源于这些参数矩阵所编码的变换关系，通过超过千亿次的矩阵乘法实现复杂的模式学习。

### [全连接层](https://juejin.cn/post/7226629485369557048)

全连接层（Fully Connected Layer），也称为密集连接层（Dense Layer），是深度学习神经网络中最常用的一种层，通常用于将卷积层、池化层等的特征提取结果进行分类或回归等任务。

全连接层的输入通常是一个二维矩阵，也可以是一个一维向量。如果输入是一个二维矩阵，那么通常需要将其先展开为一维向量，然后再进行全连接操作。假设输入是一个大小为 N×M 的矩阵，其中 N 表示样本数，M 表示特征数，则全连接层的输出可以表示为：

![image.png](https://p6-juejin.byteimg.com/tos-cn-i-k3u1fbpfcp/3337360d9a2e4a16addc727109ae0e1c~tplv-k3u1fbpfcp-zoom-in-crop-mark:1512:0:0:0.awebp?)

其中，X 表示输入矩阵，W 表示权重矩阵，b 表示偏置向量，Y 表示全连接层的输出。在这个公式中，X 和 Y 都是 N×D 的矩阵，W 是 D×C 的矩阵，b 是 1×C 的向量，D 表示输入特征的维数，C 表示输出类别的数目。

在计算输出时，我们先将输入矩阵 X 展开成一维向量，然后与权重矩阵 W 相乘，再加上偏置向量 b，最后通过一个激活函数（例如 ReLU）将输出进行非线性变换，得到全连接层的最终输出 Y。

### 开环测试/闭环测试

- 开环：系统**仅感知环境但不执行控制动作**，或者其控制输出**不被实际执行**来影响车辆状态。测试关注点在**感知、预测、规划决策模块的中间输出结果**；
- 闭环： 系统构成一个**完整的反馈回路**。感知模块获取环境信息，决策规划模块生成控制指令，**控制指令被发送给车辆执行器（或高精度车辆动力学模型）执行**，车辆状态发生变化，环境（可能包括其他智能体）对此变化做出反应，感知模块再获取新的环境状态，如此循环。测试关注整个系统的**端到端行为和性能**。

### GPU/GPGPU

GPGPU是指通用计算GPU（General-Purpose computing on Graphics Processing Units），也叫做通用GPU计算（General Purpose GPU Computing），是指利用GPU进行通用计算的技术。GPGPU可以将GPU的并行计算能力应用于科学计算、数据分析、机器学习等领域，提高计算速度和效率。
与传统GPU相比，GPGPU具有以下差异：

- 设计目标不同：传统GPU的设计目标是提供高性能的图形渲染能力，而GPGPU的设计目标是提供高性能的通用计算能力；
- 支持的计算任务不同：**传统GPU主要支持图形渲染相关的计算任务，如顶点处理、像素处理、纹理处理等；而GPGPU支持更广泛的计算任务，包括浮点计算，整数计算、向量计算等；**
- 计算精度不同：**传统GPU通常使用单精度浮点数进行计算，而GPGPU可以支持双精度浮点数和定点数等多种类的计算精度；**
- 计算模型不同：传统GPU通常使用固定的图形渲染管线来执行计算任务，而GPGPU可以使用自定义的计算模型，以适用不同的计算任务和应用场景；
- 编程模型不同：传统GPU的编程模型通常是命令式编程，需要开发者手动管理GPU内存和计算流程，而GPGPU的编程模型通常是声明式编程，通过定义一系列计算操作来描述计算流程，由编译器和运行时系统自动管理内存和计算流程；
- 程序设计不同：**传统GPU的程序设计主要是图形API，如OpenGL、DirectX等；而GPGPU的程序设计主要是通过计算API，如CUDA、OpenCL等；**
- 性能表现不同：GPGPU相对于传统GPU在通用计算任务上具有更高的性能表现，但在图形渲染任务上可能不如传统GPU；
- 存在形式不同：GPGPU通常是会被集成GPU当中，而GPU则是作为一个单独的模块，也就是独立显卡核心或者主板集成显卡核心；
- 内存架构不同：传统GPU通常使用分层内存架构，包括显存和系统内存，而GPGPU通常使用统一内存架构，将GPU内存和CPU内存合并成一个虚拟的内存池；
- 硬件支持不同：**传统GPU通常有专门的硬件支持，如纹理单元、像素处理单元等，而GPGPU通常具有更多的通用计算单元和高速缓存，以支持更广泛的计算任务；**
- 软件支持：传统GPU通常具有丰富的图形API和图形引擎支持，而GPGPU通常需要额外的软件和算法支持，以充分发挥其性能优势；
- 应用场景不同：传统GPU主要用于图形渲染和游戏开发，而GPGPU主要用于科学计算、数据分析、机器学习等领域。

**总的来说，GPGPU是一种将GPU的并行计算能力应用于通用计算的技术，可以提高计算速度和效率，具有广泛的应用场景。**

### BF16/FP16

BF16 和FP16 都是16 位浮点数，但它们在指数位和尾数位的分配上有所不同，导致了不同的数值范围和精度。BF16牺牲了尾数精度，以获得更大的数值范围，更适合深度学习中的训练，而FP16则在较小数值范围内提供更高的精度，更适合对精度要求较高的计算场景。

### 注意力模块

注意力机制是Transformer模型的心脏，它赋予模型洞察句子中每个单词与其它单词间错综复杂关系的超能力。在Transformer中有三种注意力结构：

- 全局自注意力，掩码自注意力和交叉注意力，具体如下图所示。
- 交叉注意力主要用于处理两个不同序列之间的关系；全局自注意力主要用于处理单个序列内元素之间的关系；
- 掩码自注意力（也被称做因果自注意力）通过掩码来控制模型在计算注意力分数时的关注范围，从而确保在解码时不会受到未来信息的影响。

![img](https://img2024.cnblogs.com/blog/1850883/202502/1850883-20250209144227590-945674250.jpg)

三种注意力模块在Transformer网络对应位置如下图所示。

![img](https://img2024.cnblogs.com/blog/1850883/202502/1850883-20250209144236400-880372719.jpg)

Transformer实际上是通过三重注意力机制建立起了序列内部以及序列之间的全局联系。我们具体分析下这三种注意力。

#### 全局自注意力层

全局自注意力层（Global self attention layer）位于编码器中，它负责处理整个输入序列。在全局自注意力机制中，序列中的每个元素都可以直接访问序列中的其它元素，从而与序列中的其他元素建立动态的关联，这样可以使模型更好地捕捉序列中的重要信息。自注意力的意思就是关注于序列内部关系的注意力机制，那么是如何实现让模型关注序列内部之间的关系呢？自注意力将query、key、value设置成相同的东西，都是输入的序列，就是让注意力机制在序列的本身中寻找关系，注意到不同部分之间的相关性。

对于全局自注意力来说，Q、K、V有如下可能：

- Q、K、V都是输入序列。
- Q、K、V都来自编码器中前一层的输出。编码器中的每个位置都可以关注编码器前一层输出的所有位置。

再细化来说，Q是序列中当前位置的词向量，K和V是序列中的所有位置的词向量。

#### 掩码自注意力

掩码自注意力层或者说因果自注意力层（Causal attention layer）可以在解码阶段捕获当前词与已经解码的词之间的关联。它是对解码器的输入序列执行类似全局自注意力层的工作，但是又有不同之处。

Transformer是自回归模型，它逐个生成文本，然后将当前输出文本附加到之前输入上变成新的输入，后续的输出依赖于前面的输出词，具备因果关系。这种串行操作会极大影响训练模型的时间。为了并行提速，人们引入了掩码，这样在计算注意力时，通过掩码可以确保后面的词不会参与前面词的计算。

对于掩码自注意力来说，Q、K、V有如下可能：

- Q、K、V都是解码器的输入序列。
- Q、K、V都来自解码器中前一层的输出。解码器中的每个位置都可以关注解码器前一层的所有位置。

再细化来说，Q是序列中当前位置的词向量，K和V是序列中的所有位置的词向量。

#### 交叉注意力层

交叉注意力层（Cross attention layer）其实就是传统的注意力机制。交叉注意力层位于解码器中，但是其连接了编码器和解码器，这样可以刻画输入序列和输出序列之间的全局依赖关系，完成输入和输出序列之间的对齐。因此它需要将目标序列作为Q，将上下文序列作为K和V。

对于交叉注意力来说，Q、K、V来自如下：

- Q来自前一个解码器层，是因果注意力层的输出向量。
- K和V来自编码器输出的注意力向量。

这使得解码器中的每个位置都能关注输入序列中的所有位置。另外，编码器并非只传递最后一步的隐状态，而是把所有时刻（对应每个位置）产生的所有隐状态都传给解码器，这就解决了中间语义编码上下文的长度是固定的问题。

![img](https://img2024.cnblogs.com/blog/1850883/202502/1850883-20250218212308574-176454824.jpg)

或者从另一个角度来理解，交叉注意力是序列到序列模式；双向自注意力是自编码模式；单向自注意力是自回归模式。

### Flash Attention

标准注意力算法在GPU内存分级存储的架构下存在两个缺陷：显存占用多和HBM读写次数多。具体来说就是在标准注意力计算过程中产生的S和P这两个中间矩阵过大，造成了多次读写HBM的操作。

FlashAttention的主要优化思路是：**减少大尺寸的中间矩阵在 HBM 和 SRAM 之间的换入换出，即通过利用更高速的上层存储计算单元，减少对低速更下层存储器的访问次数，来提升模型的训练性能。**可以说，FlashAttention主要是从GPU block/thread并行度的视角对访存进行了优化，而非节约FLOPs。

为此 FlashAttention 提出了两种方法来分布解决上述问题：tiling 和 recomputation。本质是对矩阵连乘问题进行定制化的的Tiling+重计算。

- Tiling（分割输入，在前向传播和后向传播时使用）。将输入的Q、K和V进行分块，然后把小块从HBM加载到SRAM中。然后按块去计算注意力。在将每个块的输出相加之前，将其按正确的归一化因子进行缩放，从而得到正确的结果。最后再写入HBM，整个过程不需要保存中间矩阵S和P。
- recomputation（重计算，仅在后向传播时使用）。在反向传播过程中不保留整个注意力权重矩阵，而是只保留前向过程中的某些中间变量（比如归一化因子），然后在反向传播过程中重新计算注意力权重矩阵。重计算虽然导致FLOPS增加，但是由于目前GPU的计算效率要高于显存访问，大量减少HBM访问也可以使FlashAttention的运行速度更快。

### Sparse Attention

attention 是 transformer 的核心机制，标准的Attention机制在计算时需要考虑到每一对输入元素之间的关系，这会导致计算量和内存消耗急剧增加，尤其是在处理长序列时。**Sparse Attention（稀疏注意力）通过在计算时仅关注部分重要的输入元素**，从而大大减少了计算和存储的开销。

优势：

- 能够将计算量从  O(n^2) 降到  O(n) 或 O(n \log n) ；
- 由于不需要存储整个注意力矩阵，Sparse Attention在内存使用方面更加高效，特别适用于处理长序列；

挑战：

- 选择怎样的稀疏模式，才既保证计算效率，又不损失重要的信息，是工程化面临的主要挑战；
- 稀疏化需要特殊的数据结构和算法来处理稀疏矩阵的乘法等操作，增加模型部署复杂度；
- 过度稀疏化可能导致模型遗漏重要的信息，进而影响模型的性能；

### LORA

LLMs的巨大规模，往往达到数十亿参数量，在微调过程中带来了计算复杂度和资源需求上的重大挑战。为应对这些挑战，一种名为参数高效微调（PEFT）的有前途的方法有望在不增加大量可训练参数的前提下将大语言模型适应于下游任务，从而减少计算和内存开销。在这类方法中，由于其有效性和简洁性，低秩适应（LoRA）受到了广泛关注。

LoRA 的核心思想是利用低秩矩阵来近似模型参数的变化，从而以极小的参数量来实现大模型的间接训练。LoRA 冻结预训练模型的权重，引入低秩矩阵和来近似模型参数的变化量。通过仅在微调过程中更新这些低秩矩阵，LoRA在保持预训练模型大部分参数不变的情况下，实现对特定任务的适应。LoRA的目标就是以小博大，以极小的参数量来实现大模型的间接训练，逼近全量微调的效果。这种方法在减少存储和计算需求的同时，也保持了模型的性能。

### [LLM 投机采样](https://zhuanlan.zhihu.com/p/653734659)

指的是用小模型的输出去投机。因为存在很多样板话，小模型也能生成的很好。比如我希望写一个 SQL 来获取所有成绩大于 30 分的学生，

```
SELECT * FROM student WHERE score > 30
```

这个前面的 SELECT * FROM 就是样板话，小模型也能正确生成。让小模型先生成一段简单的，再让大模型去生成后面一段复杂的，这样就能减轻大模型的运算量。

举个例子，

```
prefix：【Q：请写一首李白的诗。A:】
小模型生成 ： 【好的，这是一首李白的诗歌：李白李白的的的】
大模型打分：【好的，这是一首李白的诗歌】 -> 这段写的没问题 (即p(x)/q(x)大于阈值)，【李白李白的的的】->这段写的什么玩意(即p(x)/q(x)小于阈值)
大模型生成后续t：【君不见黄河之水天上来】
最后结果为：prefix【Q：请写一首李白的诗。A:】+x[1..n]【好的，这是一首李白的诗歌：】+t【君不见黄河之水天上来】
```

### 词表精简

在LLM中，词表(vocabulary)是模型能够识别和处理的所有token(标记)的集合。现代LLM通常使用**子词(token)级别的词表**，而非传统单词级别，主要通过以下算法生成：

- Byte Pair Encoding (BPE)
- WordPiece
- SentencePiece

标准LLM词表大小通常在**30,000-50,000个token**之间，某些大型模型(如PaLM)可能达到**256,000**甚至更大。词表精简能够：

- **降低计算和存储成本**

  - 词表大小直接影响模型输出层的参数量：`hidden_size × vocab_size`

  - 例如：7B模型中，若hidden_size=4096，vocab_size=50,000，则输出层参数约为205M(占总参数3%)

  - 精简词表可显著减少这部分参数

- **提高推理效率**

  - softmax计算复杂度与词表大小成正比

  - 较小词表加速推理过程，尤其对边缘设备友好

- **适应特定应用场景**

  - 通用大模型词表包含大量不常用词汇

  - 针对垂直领域(如医疗、法律)可保留相关词汇，移除无关词汇

- **降低部署门槛**
  - 小词表模型更适合资源受限环境(手机、IoT设备)

### 训练和推理的区别

在大部分情况下训练与推理差异如下：

- 训练过程： 前向传播  -> 后向传播 -> 梯度更新。（迭代重复）
- 推理过程： 前向传播 。 （迭代重复）

推理只是完成了训练的一部分内容，当然推理还可以剪枝、压缩让前向传播更快。但总体而言完成一次迭代（同batch_size），训练需要的运算量更多，但前向传播的底层运算基本相同。
