## 1. 测试套件概述

SPECCPU2017 包含四个测试套件：

| 套件 | 编号范围 | 说明 |
|------|---------|------|
| SPECrate2017\_int | 500.x\_r | 整数吞吐，多 copy 并行，每 copy 单线程 |
| SPECspeed2017\_int | 600.x\_s | 整数单流，允许多线程/OpenMP |
| SPECrate2017\_fp  | 500.x\_r | 浮点吞吐，多 copy 并行 |
| SPECspeed2017\_fp | 600.x\_s | 浮点单流，允许 OpenMP |

- **Rate** 测试：强调吞吐，每个 copy 独立运行，内存总压力 = 工作集 × copy 数
- **Speed** 测试：强调单任务完成时间，可充分利用多线程并行

### 500/600.perlbench — Perl 解释器

| 属性 | 描述 |
|------|------|
| 来源 | Perl 5.22.1，执行 spam 过滤、ClamAV 病毒库、smail 邮件程序脚本 |
| 语言 | C |
| 内存工作集 | 约 200 MB / copy |
| 向量化潜力 | 无 |
| 多线程 | 否（Rate 下多 copy） |

**计算特征：**
- 大量间接函数调用（Perl opcode dispatch table）
- 哈希表操作、字符串处理、正则匹配
- 大量短寿命对象分配与回收

**分支行为：**
- 分支极密集，每条 Perl 指令对应多次间接跳转
- BTB（分支目标缓冲）压力极大，预测准确率低

**主要瓶颈：**
- 前端（指令供给）、间接跳转预测器
- ROB（指令重排序缓冲）容量
- L2/L3 延迟（工作集超 L2）

**架构敏感度：**
- 对 BTB 容量、间接分支预测器设计高度敏感
- 代表后端服务器解释型语言（Python/Ruby/Perl）类工作负载

**优先级：** ⭐⭐⭐⭐⭐（整数综合代表性最强之一）

**优先级：** ⭐⭐⭐⭐⭐（整数最重要的综合性项目）

### 505/605.mcf — 最小费用流（网络调度优化）

| 属性 | 描述 |
|------|------|
| 来源 | 城市交通调度优化算法（Choi & Goldberg 1997 LEMON 图库） |
| 语言 | C |
| 内存工作集 | 1–4 GB / copy（ref size）|
| 向量化潜力 | 无 |
| 多线程 | 否 |

**计算特征：**
- 大型稀疏图上的最短路计算（Bellman–Ford 变种 SSSP）
- 频繁的链式指针追踪（`node->arc->node->...`）
- 访问模式完全随机，无空间局部性

**分支行为：**
- 分支密集，分支目标高度不规则
- 无法用历史记录有效预测

**主要瓶颈：**
- **DRAM 延迟**（业界公认 LLC miss 率最高的单项）
- LLC 容量（工作集远超典型 LLC）
- 内存访问并行度（MLP，Outstanding Miss 数量）

**架构敏感度：**
- 是**评估内存子系统延迟最直接的子项**
- 对 HBM、CXL 内存、NUMA 距离差异放大最为明显
- 增加 LLC 容量、降低 DRAM 延迟可显著提升分数

**优先级：** ⭐⭐⭐⭐⭐（内存延迟最权威的单一测试项）

### 503/603.bwaves — 爆炸波动力学仿真

|------|------|
| 来源 | Sandia 国家实验室爆炸仿真代码 |
| 语言 | Fortran 90 |
| 内存工作集 | 约 500 MB / copy |

| 多线程 | 是（OpenMP） |

- 3D 有限差分 stencil，规则网格时间推进

**架构敏感度：**
- 对内存带宽极度敏感，增加内存通道数效果立竿见影
- HBM 相对 DDR 优势可达 2–3×

**优先级：** ⭐⭐⭐⭐⭐（内存带宽最权威的浮点测试项之一）

## 5. 资源受限场景下的推荐子集

### 场景 A：全面快速验证整机能力（运行时间目标 < 2h）

```
502.gcc_r        INT  综合IPC，覆盖面最广
505.mcf_r        INT  内存延迟代表
525.x264_r       INT  SIMD整数代表
508.namd_r       FP   FP SIMD代表
519.lbm_r        FP   内存带宽代表
```

运行方式（Rate，copy 数等于核心数）：
```bash
runcpu --config=<cfg> --copies=$(nproc) --iterations=1 \
       --size=ref --action=run --tune=base \
       502.gcc_r 505.mcf_r 525.x264_r 508.namd_r 519.lbm_r
```

---

### 场景 B：专项验证内存子系统（带宽、延迟、NUMA）

| 测试目的 | 推荐子项 | 原因 |
|---------|---------|------|
| 内存**延迟**极限 | 505.mcf\_r | LLC miss 率最高，延迟放大最明显 |
| 内存**带宽**极限 | 519.lbm\_r | Bytes/FLOP > 10，纯带宽受限 |
| 带宽+向量化联合 | 503.bwaves\_r | 规则 stencil，向量化收益与带宽共同决定 |
| 指针追踪+延迟 | 520.omnetpp\_r | 不规则指针追踪，延迟敏感 |
| 多线程带宽扩展性 | 628.pop2\_s | OpenMP 大工作集，NUMA 影响显著 |

---

### 场景 C：专项验证 SIMD / 向量化能力

| 推荐子项 | 向量化方向 | 说明 |
|---------|-----------|------|
| 508.namd\_r | FP SIMD (double) | 分子力场，FMA 密集 |
| 525.x264\_r | INT SIMD | 视频编码，NEON 代表 |
| 538.imagick\_r | INT+FP SIMD | 混合像素处理 |
| 544.nab\_r | FP SIMD + 超越函数 | sin/cos 批量，FP pipeline |
| 507.cactuBSSN\_r | FP SIMD (高密度) | FEM stencil，接近计算上限 |

---

### 场景 D：极简验证（单项最具代表性）

| 资源极限仅运行 1 项 INT | 资源极限仅运行 1 项 FP |
|----------------------|----------------------|
| **505.mcf\_r**（内存延迟最佳代表） 或 **502.gcc\_r**（综合 IPC 最佳代表）| **519.lbm\_r**（内存带宽最佳代表） 或 **508.namd\_r**（FP SIMD 最佳代表）|

---

### 场景 E：可优先跳过的子项（资源受限时）

| 子项 | 跳过原因 |
|------|---------|
| exchange2 | 工作集极小，完全在 L1/L2 内，几乎只测量 IPC，无法区分内存/SIMD 差异 |
| deepsjeng | 工作集小，内存子系统影响极低，区分度有限 |
| leela | 综合但区分度低，leela 与 deepsjeng 测试重叠度高 |
| povray | 综合性好但无特别突出的敏感维度 |
| roms / fotonik3d | 与 bwaves/lbm/wrf 测试重叠，可用后者替代 |
| pop2\_s | Speed 专有，需 OpenMP 且问题规模极大，时间成本高 |
